## Touched outside the ticket's named "Lane owns" list, and why

The ticket names `frontend/src/app/leg-verdicts/route.ts (only if needed)` in
Lane owns, and it was needed: `POST /api/leg-verdicts` spends metered
Anthropic calls inside the shared `AgentBudget` (`backend/agents/leg_verdict.py`,
`LegVerdictConfig`), the same shape as `/api/scout/{ticker}`, so it requires
`APP_AUTH_TOKEN` and needs a token-holding proxy the browser cannot hold
itself.

Wiring that route in correctly touches two files the ticket does not list:

- `frontend/src/middleware.ts` -- added `"/leg-verdicts"` to
  `JSON_ROUTE_HANDLERS`. Without this an unauthenticated `POST` to the new
  route gets redirected to an HTML login page instead of a JSON 401, which
  every `fetch` in this repo reads as success (the exact failure mode
  `middleware.ts`'s own comment names).
- `tests/test_token_proxy_routes.py` -- added `"leg-verdicts"` to
  `TOKEN_HANDLERS`. `test_the_inventory_is_complete` asserts the on-disk
  route-handler set equals this tuple exactly, so adding the route without
  this edit makes that test fail on an unrelated-looking assertion.

Both edits are additive, one line each, in the same shape as every existing
entry in both files (see `/scout-desk`'s block in each for the precedent).
I judged this in-scope because the ticket's own Done-when line runs
`tests/test_token_proxy_routes.py` and it cannot pass without them -- but
flagging it here per the lane protocol, since neither file is in the
ticket's Lane owns list. If the integrator would rather these two edits
live in a separate commit or be redone by hand, they are cleanly
separable: `git show 77d7127 -- frontend/src/middleware.ts
tests/test_token_proxy_routes.py`.

## Assumptions made (ticket was silent)

- **The GET half needs no proxy.** `fetchLegVerdicts` reads
  `GET /api/leg-verdicts` directly through `next.config.ts`'s `/api/:path*`
  rewrite (the same pattern as `/api/board`, `/api/parlays`), since a plain
  read spends nothing and every other unauthenticated read in this repo
  works this way. Only the spending `POST` goes through the token proxy.
- **`ParlayCards.tsx` needed `"use client"`.** It had none before (pure
  presentational, no `fetch`, no `async`); `LegBuys`'s `<details onToggle>`
  needs a client component to hold the handler, and marking the whole file
  client is safe here since every import it already carries
  (`ManualTicket`, `PriceOnKalshi`, `RecordParlay`, `RefreshWhenPriced`) is
  itself already `"use client"`.
- **`<LegVerdicts>` renders above BOTH `<AskTheMarket>` call sites** in
  `PriceOnKalshi.tsx`'s `Result` (the `book_empty` branch and the `priced`
  branch), not just one -- the ticket said "renders just above
  `<AskTheMarket>`" without specifying which occurrence, and both are
  reachable from a "Price on Kalshi" tap.
- Added one glossary entry (`advisory`) since the ticket's header line names
  a term to gloss and none of the existing 40-odd entries fit.
